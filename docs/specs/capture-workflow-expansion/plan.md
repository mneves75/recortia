## Implementation order

### 1. Preview the current capture and export an optimized copy

**First slice** Add **Preview** to the existing thumbnail. Show a larger nonactivating AppKit panel from a sanitized, downsampled in-memory render. Give it a keyboard action, Escape to close when focused, and a deterministic focus return. Use the thumbnail’s existing capture owner and pixel budget. A pointer over either surface or explicitly requested keyboard focus holds the same timer. When both are clear, start the current eight-second countdown. Hide both surfaces during the next selection and recover the same surviving capture after a cancellation. Replacement, expiry, dismissal or quit releases both surfaces and the render. Keep the preview inside the originating display’s usable area. Investigate a system Quick Look panel only if secure file lifetime and any OS cache behavior can be demonstrated on a dedicated test desktop. [Recortia thumbnail decision](https://github.com/mneves75/recortia/blob/5cc56cea9ee3a0fa4ab766758579b1c10b76e49e/docs/adr/0009-quick-action-thumbnail.md) · [Apple Quick Look panel](https://developer.apple.com/documentation/quicklookui/qlpreviewpanel)

**Second slice** Add **Save Optimized Copy…** within the thumbnail’s actions. Reuse `QuickActionsModel`, `ExportCoordinator`, the automatic PNG/JPEG encoder and the Save panel. Prepare one sanitized export with the chosen format, pixel dimensions and actual bytes. Always confirm the destination in the panel, even with a preferred folder set. Prefill the actual encoded extension and recheck replacement consent for the exact output path. Save those same bytes after approval. Preserve transparent pixels where automatic export keeps PNG and use the existing opaque matte when JPEG is selected. Cancellation, a stale render or write failure preserves both the current capture and any existing destination file. Copy continues to use the existing PNG clipboard path. [Export contract](../../../SPEC.md#fr-07--export-and-explicit-side-effects)

**Third slice** Add **Copy Text** in the same actions menu. Run existing on-device OCR over the sanitized revision at adequate resolution. Copy only the result of the still-current action. An empty result, cancelled OCR, failed masking or a stale capture leaves the clipboard unchanged. Use the existing EN/pt-BR OCR and clipboard behavior as the baseline. [Recognition contract](../../../SPEC.md#fr-08--ocr-and-qr) · [Editor recognition path](https://github.com/mneves75/recortia/blob/5cc56cea9ee3a0fa4ab766758579b1c10b76e49e/Packages/RecortiaKit/Sources/Features/EditorModel%2BRecognition.swift)

**Acceptance** Open, close and replace the preview using pointer and keyboard on single- and mixed-scale displays. Start a new selection and verify both surfaces hide without taking foreground focus. Cancel, verify restoration and expiry, then repeat with a successful replacement and a late preview/export/OCR callback. Verify VoiceOver names, focus return, light/dark rendering through `ChromeAppearance`, and hidden or minimized app behavior. Two inputs differing only under the same mask must produce identical permitted preview and export artifacts. Save a photo and a transparent line-art image. Check actual output type, bytes, metadata and saved size against the previewed choice. Exercise save with a preferred folder, a destination file collision, a cancelled replacement, and a stale render. Verify the existing file survives the last two. Verify existing Copy, Pin, Save, auto-redaction refusal and Dismiss still work in both languages. For OCR, exercise reading order, accents, an empty result, a cancellation, and masked text. Test only with synthetic inputs.

### 2. Reusable framing and watermarks

**First slice** Extend the existing `Presentation` and saved-default workflow with named user-owned framing recipes. Store only typed style values in preferences. Applying a recipe to the open editor is one undoable document change. Renaming a recipe, changing the default, or importing an older preference file must preserve open documents. Keep one explicit default and a clear reset. Validate bounds, duplicate names, and stale or missing recipes at the existing settings boundary. Ship the app-owned text/solid/gradient options first. Any later user-selected background image needs a separate decision about access and storage.

**Second slice** Add a simple border and an optional text watermark with position, opacity and rotation. Use the existing controlled composition renderer and shared geometry so preview, save, copy, drag and print agree. Define the order once: secure replacement, normal composition and output decoration, then clean encoding. Any later perspective or progressive blur effect belongs after secure replacement and shares the same coordinate mapping and output limits. Keep any cosmetic blur clearly distinguished from secure redaction. [Redaction and composition contracts](../../../SPEC.md#fr-06--redaction)

**Acceptance** Apply each style with and without a mask at multiple output scales. Check rendered pixels and alpha in actual exported files, clipping at every edge, undo/redo, safe defaults on legacy preferences, imports remaining unchanged, and matching previews in both languages. Exercise empty, unusually long and Unicode watermark text. Confirm that a new style never produces a different output when the only input difference is masked source data.

### 3. Add an opt-in local after-capture workflow

Start with **Pin** beside the existing editor and thumbnail presentation choices for ordinary still captures. Use `AppModel`’s capture-completion dispatch, `AutomaticExportPlan` and `PinsModel`. Decide the presentation and side-effect plan once at capture completion, before suspension. If automatic masking is on, open the editor even when masking succeeds. Never show a thumbnail or auto-pin that capture. Existing automatic exports may proceed only after the mask barrier succeeds. Keep Capture Text, scrolling capture and import on their existing routes. Revalidate each enabled side effect at delivery using its original folder or consent identity. Preserve standalone automatic copy/save behavior and its current order. Make pin refusal visible and keep an available local editor/thumbnail route on failure. Extend preferences compatibly through an optional setting that older records can omit. [Recortia thumbnail decision](https://github.com/mneves75/recortia/blob/5cc56cea9ee3a0fa4ab766758579b1c10b76e49e/docs/adr/0009-quick-action-thumbnail.md)

Only design named workflows after this slice demonstrates a second real use case. The supported actions would be typed existing Recortia operations chosen inside the app. Settings must show the resulting action order and expose destination choices. Keep data lifetimes tied to their owners and avoid duplicated Copy/Save when both an existing toggle and a recipe mention one. Wire no new upload provider or external trigger through this work.

**Acceptance** Verify Pin alone, Pin plus explicitly enabled Copy or Save, pin budget refusal, permission loss, and closing or replacing the current capture with work outstanding. With Pin selected and automatic masking enabled, verify that both masking success and failure open the editor and neither creates a pin. Verify zero automatic exports before mask success, exactly one delivery per enabled action, safe behavior if settings or destination change mid-flight, and no new network call or credential access on a clean install. Exercise ordinary window activation, menu-bar presence, and no unwanted focus switch under the physical Space test.

## Separate decisions and later discovery

- **Notch cropping.** The reference implementation combines display safe-area metadata with a black-strip heuristic. Recortia should keep exact capture geometry by default. An opt-in crop can proceed only if tests can distinguish a hardware strip from real black content, including at mixed scale, in fullscreen and on displays without a notch. A post-capture trim command is the fallback when the pixels are ambiguous. [Reference crop logic](https://github.com/fayazara/screendrop/blob/71c40179229b5e3060737b963f1ffa346484f88b/Screendrop/NotchBarTrimmer.swift#L21-L54)
- **Library and editable files.** The existing ten-minute memory slot serves immediate recovery. Decide user-selected folder browsing separately, including refresh and deletion semantics. Keep project file and Finder Quick Look work behind ADR-013 because editable source pixels change what can be recovered from a masked document. [Recortia ADR-013](https://github.com/mneves75/recortia/blob/5cc56cea9ee3a0fa4ab766758579b1c10b76e49e/docs/adr/0013-project-files.md)
- **Video-only recording.** If approved as its own milestone, first qualify an explicit selected target, visible recording indicator and Stop, cancellable start and finish, a bounded frame queue, and output only to a person-chosen local file. Confirm all selected content fits the original target and stop on display/permission/lock changes. Compare ScreenCaptureKit recording output with a bounded AVFoundation writer from actual macOS 26.0 tests. Add trim and export only after that path is stable. This decision needs a SPEC amendment and threat model before code. [Apple ScreenCaptureKit sample](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)
- **Automation and cloud.** ADR-011 (local automation) and ADR-012 (the incoming Share entry point) are blocked. S3 is proposed in ADR-014 and awaits owner signature. A hosted player, comments, background uploads, and publishing media sidecars would each change the product’s data-handling contract. Existing GitHub consent applies only to the reviewed GitHub destination. [Recortia extensions contract](../../../SPEC.md#13-optional-extensions) · [Recortia ADR-014](https://github.com/mneves75/recortia/blob/5cc56cea9ee3a0fa4ab766758579b1c10b76e49e/docs/adr/0014-s3-upload.md)

## Delivery gates

1. Approve the first slice, then write its acceptance spec and tickets before implementation. Preserve the macOS 26.0 floor and keep existing languages and direct-distribution settings. Choose product limits for preview pixels and recipe count from measurements before claiming capacity.
2. Keep the existing end-to-end scenarios and add behavior-level coverage only where the changes create a distinct risk or flow. Measure production targets with `cccc`; avoid new tests for scores of 5 or lower unless the code contains a regular expression. Reuse the existing RED suite for any capture, preview, composition, export or clipboard changes.
3. Run `./init.sh check --unsigned`, focused native EN/pt-BR checks, then the full bilingual gate and source-blind visual review. Qualify native keyboard, VoiceOver, Spaces, permissions, exact saved bytes, and the minimum macOS build on a dedicated test desktop. Record observed statuses with the existing `scripts/tests-report.py` and track incremental evidence in `progress.md`.
4. Use `mneves-prune-tests` for approved duplicates with replacement evidence and `mneves-verify` for independent acceptance. Candidate documentation, version and release work follow verified scope, with the repository’s exact-commit security and signing gates.
